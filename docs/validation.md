## 功能与安全测试

`tests/reader.test.mjs` 为每项测试创建独立的 DOM、文件对象和存储状态，使用随仓库提供的 Marked、DOMPurify 和应用脚本。覆盖以下场景：

1. HTML 的本地脚本引用及浏览器库哈希。
2. TXT 分段与 HTML 样式输入按文字显示。
3. FileReader 的 UTF-8 文档读取。
4. FileReader 的 GBK 字节解码。
5. Markdown 标题、列表与代码渲染。
6. 脚本、iframe、事件处理属性和危险链接的清洗。
7. 进度只保存文件名、位置、时间，不保存正文。
8. 重新打开文档时恢复位置。
9. 滚动保存的 500 ms 防抖。
10. 损坏的进度 JSON 不阻止阅读。
11. 浏览器拒绝存储访问时继续阅读。
12. 未打开文件时保存的提示。
13. 不支持的文件扩展名处理。
14. 三档字号。
15. 主题切换保留其他页面类名。
16. JSON 记录导出与临时 Blob URL 释放。
17. 连续读取时，较早完成较慢的文件不会覆盖新文件。

## 如何复查

```bash
npm ci --ignore-scripts
npm run vendor
npm test
npm run audit
```

依赖告警结果只反映检查当时的公告信息；版本更新后应重新运行测试和审计。

## 验证边界

本次没有执行 Chrome、Edge、Firefox、Safari 的完整端到端兼容性测试，没有进行大文件内存或性能测试。jsdom 验证了解码、DOM、存储逻辑和导出行为，但不能代替浏览器实际下载、布局与 `file://` 存储策略检查。

阅读进度基于像素且按文件名区分；同名文档冲突、字体与窗口变化、异步图片加载均可能影响恢复位置。记录没有导入功能。这些行为也已写入 README。
